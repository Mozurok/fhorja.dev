# Fixture: description-gutted

D-6 has two failure clauses and each gets its own directory, so a RED proves one thing at a time.

`healthy/`        clears both: capability segment just over 150 chars, `Do not use` present.
`gutted-segment/` capability segment cut below 150, marker intact, so ONLY the floor clause fires.
`no-marker/`      no routing marker at all, capability text long enough that the floor alone would
                  pass, so ONLY the marker clause fires. This is the total-bypass case: without the
                  marker the whole description counts as capability and the floor stops meaning
                  anything. Measured 2026-08-10, all 98 real descriptions clear a 150 floor under
                  that rewrite.

`no-standalone-use-when/` is the discriminating one, added after review. `Do not use when ...` CONTAINS
                  the string `use when`, so an unanchored `Use when` pattern matches inside the OTHER marker, 7 chars
                  later. Its capability segment therefore reads differently under the correct and the buggy pattern,
                  and it only works as a test while that pair straddles the floor. A shape that merely lacks a
                  standalone `Use when` does NOT discriminate: it reads the same either way.

                  The two numbers live in that fixture's own SKILL.md body, next to the prose whose length sets them,
                  and deliberately NOT here as well. They were duplicated in both places for one revision and this
                  copy went stale immediately, which is the same silent-drift shape the fixture itself is testing for.
